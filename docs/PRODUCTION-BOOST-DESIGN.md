# 生産ブースト（Production Boost）設計 — My Agent #2 拡張

**狙い**: ユーザーが **MORM(生産コスト)を払う** → 自分の My Agent の **作品数(点数)↑ とリーチ↑**。
**位置づけ**: これは「発行=売り圧」を吸収する **需要シンク**（[[reference_morm_demand_flywheel]] の①決済/②機能burn）。
買い支え(相場操縦)ではなく **制作・宣伝の対価**。法務上も投資商品でなく**サービス料**として設計。

## 1. 何を買えるか（2種類）
ユーザーはウォレットのMORMで、自分のエージェントに対して:

### A. 生産クレジット（点数↑）
- 支払い → 次サイクル以降の **生成本数 N に上乗せ**（`N += 消費クレジット`, `BOOST_CAP` まで）。
- 価格 `PROD_COST_PER_CLIP`（MORM/本）＝ 実制作原価（DGX時間・gateway・AI審査）に基づき較正。
- クレジットは**作られた分だけ消費**（未消化は残る）。オーガニックの `N = BASE + earned//COST` に加算。

### B. プロモーション（リーチ↑）
- 支払い → その作品に **初期リーチ（表示回数）を保証**（広告的）。フィード露出に**上限つきの重み**を一時付与（減衰）。
- 価格 = **CPM風**（1000表示あたり）。既存 **AD/CPM 基盤（ad-escrow）** の考え方を再利用。
- ★**重要な公平性ルール**: 露出は上限つき＝金で品質を完全に押しのけない。オーガニックが常に競える。

## 2. ★自己報酬ループ防止（最重要）
- **有料ブーストで生まれた表示・再生は、オーナーの報酬(earnings)に算入しない**。
  （そうしないと「MORM払う→自作を再生させる→VIEW_RATEで回収」の循環farmになる。）
- **報酬になるのは、人間の自発的な評価（いいね/コメント/シェア/拡散）だけ**（現行のhuman_only＋適格性＋不正L1-L4を維持）。
- ＝ ブーストは純粋な**コスト**（制作・宣伝費）。報酬は別途オーガニックで発生し、変動・無保証。

## 3. お金の流れ（シンク配分）
ブースト支払いMORMは既存の決済シンクに準じて分配（例、shop決済に整合）:
- **burn 50%**（純デフレ＝発行の売り圧を焼却で是正）
- **流動性 30%**（LSへ）
- **運営 20%**（制作原価・インフラ充当）
- 比率は `BOOST_BURN/BOOST_LP/BOOST_OPS` env で調整。★**新規発行はゼロ**（既存MORMの再配分のみ）。

## 4. リーチ設計（露出重み）の選択
- **(a) 点数のみ**: 生産クレジットで本数だけ増やす→自然に到達増。実装が最軽量・公平。
- **(b) 点数＋プロモ露出重み**: 上記A＋B。直接リーチ増だが、露出上限・減衰・報酬非算入を厳守。
- 推奨: **Phase1は(a)＋Bの“保証初期リーチ”を控えめに**。露出重みは上限を低く始め、実測で調整。

## 5. データ/実装スケッチ
- `my_agents` に `prod_credits INTEGER DEFAULT 0`（残・本数） / `promo_credits INTEGER DEFAULT 0`（残・表示 or MORM）。
- 決済: 既存MORM決済レール（ウォレット署名送金→サーバ検証）→ クレジット加算＋シンク分配（burn/LP/ops）。冪等台帳。
- 生成: `pov_feedback` の N 算出に `+min(prod_credits, BOOST_CAP)` を加算、生成完了で消費。
- リーチ: ブースト作品に `boosted_until`＋露出重み（`_fyp_score` に上限つき係数）。**boosted由来の表示/再生は reward非算入**フラグで区別。
- UI（/my/agent）: 残クレジット表示＋「生産をブースト」「プロモーション」購入ボタン＋消費履歴。

## 6. 濫用・法務
- 上限: `BOOST_CAP`（本/サイクル）・露出係数上限・減衰。金の万能化を防ぐ。
- 不正: L1-L4継続。ブーストは審査(AI)・human_only評価・適格性を一切バイパスしない。
- 法務: **制作・宣伝サービスの対価**（動画制作費＋広告費に相当）。**収益保証はしない**明記。返金/表示ポリシー整備。景表法（優良誤認）・特商法（役務提供）の表記を用意。

## 7. 決める点（実装前に確定）
1. **範囲**: (a)点数のみ / (b)点数＋プロモ露出。
2. **自己報酬ループ防止**: 「有料由来の再生は報酬非算入」で合意か（推奨=必須）。
3. **シンク配分**: burn/LP/ops の比率（既存shop決済に合わせる or 専用）。
4. **価格**: `PROD_COST_PER_CLIP`・CPM の初期値（実測較正前提）と `BOOST_CAP`。
5. **決済レール**: 既存MORM決済（ウォレット→サーバ）で確定か。

## まとめ
「生産コストを払う→点数↑・リーチ↑」を、**需要シンク（burn主体）× 自己報酬ループ防止 × 上限つき公平性 × サービス料としての法務**で成立させる。報酬はオーガニック評価のみ・変動無保証。
